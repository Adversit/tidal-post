## 3. 玩家场景、体验目标与创新假设

- 玩家通过控制潮水,让小纸船把信件送到对应码头。
- 核心循环:观察船与机关 → 选择潮向或下锚 → 所有船同步响应 → 水闸与船位变化 → 调整计划 → 全部完成投递。
- 核心组合:
  1. 一个方向指令同时影响所有船;
  2. 船可以压住浮标,为其他船打开水闸;
  3. 潮汐锚让一艘船暂时不随潮移动;
  4. 归港让船退出棋盘,交付顺序影响协作。
- 期望体验:“我让一艘船留下守住机关,另一艘顺利通过,最后再把它们都送回家。”
- 这是待试玩验证的差异化假设;不声称绝对原创、已证明好玩或难度曲线合理。

## 5. 实体、规则、状态转换与恢复机制(TIDE-RULES-1)

### 5.1 棋盘与对象

- 有限二维方格,不环绕;坐标为从 0 开始的 [row, col]。
- `#` 陆地/礁石不可通行;`.` 为水格。船与码头都在水格。
- 船有稳定 ID、起点与唯一对应码头;初始不重叠、不出生在码头;码头互不重叠。
- 浮标是水格上的机关,可被任意船压住,允许初始船就在浮标上。

### 5.2 潮汐移动

- 输入上/右/下/左其一;所有未锚定且能移动的船同时移动一格。
- 不滑到底、无惯性、无随机。
- 越界、陆地、关闭水闸、不能腾出的船均造成阻挡;受阻船原地不动,无惩罚。

### 5.3 船间跟随

- 后船可进入前船本次腾出的格(含前船进港)。
- 前船受阻(墙/门/锚/他船)则依赖它的后船也停住。
- 判定与 boats 数组顺序无关:先算目标格,沿潮向从前到后求 canMove(依赖前船能否移动),全部判定后一次性提交。
- 同向平移一格,不存在两船争一格;不加抢先、推船、交换规则。

### 5.4 码头

- 船进入自己的码头即交付并从棋盘移除。
- 他人码头(含已交付码头)对当前船是障碍。
- 交付后该船不再移动、不压浮标、不能被锚。
- 码头用颜色 + 邮戳形状标识对应关系。

### 5.5 水闸与浮标

- 水闸在两个正交相邻水格之间的边上,关闭时双向禁行;不存在“水闸格”。
- 原型每扇门恰好关联一个浮标(规则支持一个浮标控多门,本批不用)。
- 门的开闭统一取潮汐开始前的占用快照:
  - 开始时有船守浮标 → 本次门开;无船 → 本次门关。
  - 本次离开浮标不会中途关门;本次到达浮标不会中途开门。
  - 全部移动结算后,按新占用更新门的画面状态。
- 门状态不单独存储,始终由船位推导(`gateOpen`)。

### 5.6 潮汐锚

- L01–L04 无锚(基础教学);L05–L08 每关 1 次。
- 锚定一艘未交付船,使其在下一次**有效潮汐**原地不动。
- 锚定船仍占格、阻挡他船、可继续压浮标;其他船照常响应。
- 选择/取消/更换锚目标不消耗次数、不计移动、不进撤回历史。
- 有效潮汐 = 至少一艘船移动或交付:
  - 全体不动 → 不消耗锚、不进历史、保留待用锚目标;
  - 至少一船动 → 有待用锚则消耗一次并清除待用目标;
  - 即使被锚船本就会被墙挡住,只要潮汐有效也消耗;不替玩家豁免。

### 5.7 撤回、重来、完成

- 无限撤回:恢复上一次有效潮汐前的船位、交付状态、锚剩余次数、移动计数。
- 撤回后清除待用锚、选中状态与路径预览;门由恢复后的船位推导。
- 无效潮汐与锚选择不占撤回步数;支持连续撤回与通关后撤回。
- 重来恢复本关初始状态,清空本关历史与选择;不跨关撤回。
- 全部交付即完成;不自动进下一关,保留“下一关”与撤回入口。
- 首版无失败/Game Over:全体不动 ≠ 无解;错误规划保留现场,可继续/撤回/重来;
  不用求解器向玩家宣布不可解;不提供自动通关与参考解展示。

## 6. 技能行为契约(潮汐锚)

| 场景 | 行为 |
| --- | --- |
| 点锚按钮 | 进入选船状态;次数为 0 或本关未解锁时禁用 |
| 点船 | 设为待用锚;再点取消;点他船更换 |
| 有效潮汐结算 | 被锚船不动;消耗 1 次;清除待用锚 |
| 无效潮汐 | 不消耗;保留待用锚 |
| 撤回 | 恢复次数;清除待用锚与选中态 |
| 动画期间 | 锚按钮禁用 |

## 7. 显示结构、输入与状态反馈

- 三种潮向输入同一规则入口(`GameController.tide`):棋盘四向滑动、屏幕四向按钮、键盘方向键/WASD。
- 滑动:手势结束才提交;最小位移阈值;主轴识别;模糊对角不猜方向;不处理多指;`touch-action: none` 防止整页滚动。
- 键盘:忽略 `repeat`(长按不堆积);焦点在输入控件时不抢占。
- 锚流程:点锚按钮 → 选船状态 → 点船设待用锚 → 选潮向 → 结算一次有效潮汐。
- 状态反馈:待用锚(虚线圈 + 锚标)、移动波纹(与运动同向)、受阻(障碍处短促撞击线)、
  全体不动(轻提示“这个方向暂时走不动”)、浮标激活(下压 + 亮灯)、水闸开/关(横杆抬起/落下)、
  交付(船驶入码头、信封投递、小灯点亮)、完成(完成遮罩 + 继续入口)。
- 结算为原子操作;动画期间移动/锚/撤回/重来全禁用,结束后恢复;动画只呈现结果,不参与判定。

## 8. 视觉、声音、响应式与资产规范

- 方向:俯视纸艺微缩海港;温暖、清透、轻立体层次;规则信息始终清楚。
- 不做成网格 + 字母 + 矩形按钮的调试页;调试叠层默认关闭(本轮未提供)。
- 色彩:纸底 #F6F0E3;海水 #9BD5D4;深水/轮廓 #3F7F87;主操作/船 #E3826F;灯光 #D6AA58;文字 #244B52。
  - 为区分两艘船,B 船在允许范围内调整为低饱和青蓝 #4E8A96(对比度小幅调整,未脱离纸艺方向)。
- 对象:折纸船(明暗面 + 投影)、两种邮戳形状(A 圆形 / B 星形)与码头一致、柔边礁石、
  浮标与水闸共用水波纹机关徽记、门画在两格之间、锚以图形表现“这一拍留下”、装饰在棋盘外围。
- 层级:顶部(关卡标题 / 已投递数 / 选关 / 动效开关)— 中部棋盘 — 底部(锚 / 撤回 / 重来 / 四向键 / 提示)。
- 动效:潮汐 → 船移 → 开闸 → 投递顺序一致;日常动画短促(单次移动约 230ms);
  支持减少动态效果(系统 `prefers-reduced-motion` + 界面开关,关闭后即时结算);
  不依赖远程音乐或字体。
- 声音:本轮未添加声音(规范为“若添加则提供静音”);列入后续候选。
- 响应式:手机竖屏为主、桌面键盘可用;格子保持正方形按行列等比缩放;
  触控目标 ≥ 44 CSS px;适配 320 / 375 / 430 CSS px 与桌面;底部安全区 `env(safe-area-inset-bottom)`;
  原型 8 关全部可直接选择。
- 资产:全部为程序化 Canvas 绘制,无外链图片/字体/素材;不用 emoji 充当主要游戏资产。

## 9. 关卡职责、数据规范与递进计划

- L01《第一封信》:一格移动与匹配码头。
- L02《绕过礁石》:障碍、转弯、不滑到底。
- L03《一起出发》:同步移动、跟随、各自交付。
- L04《水闸值班》:浮标控门、回合开始快照。
- L05《一枚潮汐锚》:留一船守浮标。
- L06《多留一步》:先到浮标再定锚时机。
- L07《守住浮标》:准备位置、下锚、穿闸、再投递。
- L08《最后一封信》:综合规划与交付顺序。
- 教学:短句 + 局部状态,不弹长篇规则,不直接给完整操作序列;是否合适待真实试玩验证。
- 数据规范:见 `src/levels.ts` 与 `validateLevel`(AC12)。
- 50 关递进计划(后续阶段,仅记录):1–10 基础与锚教学;11–20 同步位移与距离协调;
  21–30 浮标位置与穿闸准备;31–40 锚的对象/时机/交付顺序;41–50 组合与挑战。
  禁止随机生成不筛选凑数、换色凑数、以“最短解更长”等同难度。
