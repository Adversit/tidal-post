## 4. 研究及实现日志

### 2026-10-15 原型实施(首轮)

- 项目初始为空目录,无 Git。默认技术栈:Vite 5 + TypeScript 5.6 + Vitest 2.1;棋盘 Canvas 2D,界面 HTML/CSS。
- 文件结构:
  - `src/types.ts` 核心类型;`src/rules.ts` 纯规则引擎(不依赖 DOM/随机数);
  - `src/levels.ts` 8 关固定数据 + `validateLevel`;`src/solver.ts` BFS 求解(仅测试用);
  - `src/game.ts` 控制器(状态/历史/锚选择/输入锁定);`src/render.ts` 纸艺海港渲染与动画;
  - `src/ui.ts` 界面与三输入;`src/main.ts` 组装入口。
  - `tests/` rules / game / levels / solver / app 五个测试文件。
- 规则要点落地:
  - 门开闭取潮汐开始前快照;门状态不存储,由船位推导(`gateOpen`)。
  - 跟随判定 memo 化,与 boats 数组顺序无关;全部判定后一次性提交。
  - 有效潮汐才消耗锚、计数、进历史;无效潮汐保留待用锚。
  - 撤回恢复船位/交付/锚次数/计数,并清除待用锚与选中态。
- 视觉:程序化 Canvas 纸艺图形(折纸船明暗面、邮戳 A 圆形/B 星形、浮标与水闸共用水波徽记、
  两格之间的门横杆、礁石柔边卵石、波纹/撞击线/信封动效);无外链资产,未用 emoji 充当游戏资产。
- B 船颜色为区分度在规范允许范围内调整为 #4E8A96(见 PRD 第 8 节)。
- 声音未添加(规范为可选项),列入后续候选。

## 8. 用户试玩复现步骤(代用户准备)

1. `npm install`(已装可跳过)→ `npm run dev`,浏览器打开提示的本地地址;
   或 `npm run build` 后用任意静态服务托管 `dist/`(如 `npx serve dist`)。
2. 重点试玩 L04–L08,并记录:
   - 是否理解“潮起时有人守浮标,这一次门才开”的时序;
   - 是否知道该把锚给谁、什么时候给;
   - 走错时是否清楚原因(提示与画面反馈);
   - 是否愿意继续玩下一关。
3. 检查项:手机窄屏(320/375/430)与桌面布局;触控滑动与键盘;水闸/浮标对应关系;
   锚的待用/消耗/解除与撤回恢复;不同长宽关卡缩放;动画期间快速输入;“动效:关”开关。
